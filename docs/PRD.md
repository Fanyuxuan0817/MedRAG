# 📄 Agentic RAG 医保问答系统 PRD

## 一、项目概述

**项目名称：** MedAgent-RAG（可替换）

**项目类型：** 多智能体驱动的 Agentic RAG 问答系统

**应用场景：** 医保政策咨询 / 药品报销 / 报销流程指导

### 🎯 项目目标

构建一个基于多 Agent 协同的智能问答系统，实现：

- 多源医疗政策数据的精准检索
- 复杂问题的自动拆解与多步推理
- 医保报销问题的一站式解答（政策 + 药品 + 流程）

***

## 二、用户与使用场景

### 👤 目标用户

- 普通用户（咨询医保报销）
- 医疗相关从业人员
- 政务服务辅助系统

***

### 🧩 核心使用场景

**示例 Query：**

> “某药品能不能报销？报多少？怎么报？”

系统需完成：

- 判断药品是否医保覆盖
- 查询报销比例（国家 + 地方）
- 给出具体报销流程

***

## 三、系统整体架构

```text
用户输入
   ↓
意图识别模块（Intent Classifier）
   ↓
Router Agent（任务拆解 + 分发）
   ↓
┌───────────────┬───────────────┬───────────────┐
│ Policy Agent  │ Drug Agent    │ Procedure Agent│
└───────────────┴───────────────┴───────────────┘
             ↓（多Agent结果）
      Verification Agent（校验）
             ↓
      Aggregator Agent（整合）
             ↓
         最终回答输出
```

***

## 四、功能模块设计

## 4.1 意图识别模块（Intent Classifier）

### 功能

- 对用户 Query 进行分类
- 支持多意图识别

### 意图类型

| 类型  | 示例      |
| --- | ------- |
| 政策类 | 报销比例是多少 |
| 药品类 | 是否在医保目录 |
| 流程类 | 怎么报销    |
| 材料类 | 需要什么材料  |
| 综合类 | 上述组合问题  |

### 输出

```json
{
  "intent": ["药品查询", "报销政策", "流程咨询"],
  "complexity": "multi-step"
}
```

***

## 4.2 Router Agent（核心调度模块）

### 功能

- 根据意图拆解任务
- 决定调用哪些 Agent
- 支持串行 / 并行执行

### 输入

```json
{
  "query": "...",
  "intent": [...]
}
```

### 输出（任务规划）

```json
[
  {"agent": "DrugAgent", "task": "查询药品是否医保"},
  {"agent": "PolicyAgent", "task": "查询报销比例"},
  {"agent": "ProcedureAgent", "task": "获取报销流程"}
]
```

***

## 4.3 六大 Agent 设计（核心）

***

### 1️⃣ Policy Agent（政策检索 Agent）

**功能：**

- 检索国家及地方医保政策
- 优先返回最新政策

**数据源：**

- 政策文档（RAG + 向量数据库）

**输出：**

```json
{
  "policy": "...",
  "source": "医保发〔2023〕25号"
}
```

***

### 2️⃣ Drug Agent（药品知识 Agent）

**功能：**

- 查询药品是否在医保目录
- 返回甲/乙/丙分类
- 查询报销限制条件

**数据源：**

- 结构化数据库（SQL / JSON）

***

### 3️⃣ Procedure Agent（流程 Agent）

**功能：**

- 返回报销步骤
- 返回材料清单

***

### 4️⃣ Location Policy Agent（地方政策 Agent）

**功能：**

- 查询各地区报销差异
- 结合用户位置（或默认）

***

### 5️⃣ Verification Agent（校验 Agent ）

**功能：**

- 多源信息交叉验证
- 检测冲突或不一致

**规则示例：**

- 国家 vs 地方冲突
- 药品目录 vs 政策描述

***

### 6️⃣ Aggregator Agent（整合 Agent）

**功能：**

- 汇总所有 Agent 输出
- 生成结构化结果

**输出格式：**

```json
{
  "是否可报销": "是",
  "报销比例": "70%",
  "限制条件": "...",
  "报销流程": [...]
}
```

***

## 五、系统流程（核心逻辑）

```text
1. 用户输入问题
2. 意图识别（多标签）
3. Router Agent 任务拆解
4. 多 Agent 并行执行：
   - Policy Agent
   - Drug Agent
   - Procedure Agent
   - Location Agent
5. Verification Agent 校验结果
6. Aggregator Agent 汇总
7. LLM生成自然语言回答
```

***

## 六、关键技术设计

### 🔹 1. RAG 检索增强

- 向量数据库（Chroma）
- 文档切分 + embedding

***

### 🔹 2. Agent 框架

- 推荐：LangGraph / LangChain Agent
- 支持：
  - Tool Calling
  - 多步推理（ReAct / Plan-Execute）

***

### 🔹 3. 多 Agent 协同

- 并行执行（提高效率）
- Router 控制流程

***

### 🔹 4. 数据融合

- 非结构化（政策文本）
- 结构化（药品目录）
- 半结构化（流程）

***

## 七、核心指标（KPI）

| 指标      | 目标        |
| ------- | --------- |
| 回答准确率   | ≥ 85%     |
| 多轮问题解决率 | ≥ 90%     |
| 响应时间    | < 3s      |
| 幻觉率     | 显著低于传统RAG |

***

## 八、项目亮点

构建基于多智能体协同的 Agentic RAG 系统，引入 Router Agent 实现任务动态拆解与分发，结合 Policy / Drug / Procedure 等多领域 Agent 完成复杂查询，并通过 Verification Agent 进行多源信息校验，显著提升问答准确性与可解释性。

***

## 九、可扩展方向

- 用户画像（不同城市自动匹配政策）
- Memory Agent（上下文记忆）
- 实时政策更新（爬虫 + 增量索引）
- 多模态（上传药单识别）

***

# ✅ 一句话总结（PRD版本）

本系统通过 6 个功能明确的 Agent 协同，实现从用户问题理解 → 多源数据检索 → 结果校验 → 结构化输出的完整闭环，解决传统 RAG 在复杂政策问答中的准确性与可靠性问题。
